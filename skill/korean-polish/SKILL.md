# 한국어 원고 다듬기

## 왜 이 절차를 따르는가

Claude가 쓴 한국어에는 뜻은 통하지만 읽기 불편한 문장이 섞인다. 영어 문장의 틀을 옮겼거나, 주어와 목적어를 생략했거나, 명사를 기호로 이어 붙인 문장이다. 실험으로 확인한 사실이 세 가지 있다.

- Claude는 이런 문장을 스스로 가려내지 못한다. "어색한가?"라고 물으면 대부분 자연스럽다고 답한다.
- 편집자가 직접 판정한 문장을 예시로 주면 편집자의 기준을 읽어 내서 처음 보는 문장에 적용한다.
- 글을 쓴 대화 안에서는 자기 문체를 그대로 따라간다. 고치는 일은 그 글을 쓰지 않은 새 맥락에서 해야 한다.

그래서 이 스킬의 기준은 `labels.jsonl`의 판정 기록뿐이다. 어떤 단어가 나쁜지, 어떤 문형이 나쁜지 스스로 규칙을 만들어 적용하지 않는다. 직접 세운 규칙은 편집자의 기준과 어긋난 적이 있다(예: 비유 표현이 문제라고 예상했지만 편집자는 생략이 채워진 문장을 비유가 남아 있어도 받아들였다).

## 절차

스크립트는 이 스킬 폴더의 `scripts/polish_tools.py`다. 아래에서 `TOOLS`는 그 경로를 가리킨다.

### 1. 구간 나누기

```bash
python TOOLS chunks 원고.md
```

구간마다 `시작줄 끝줄`이 한 줄씩 나온다. 사용자가 일부만 고치라고 했으면 해당하는 구간만 고른다.

### 2. 구간마다 새 하위 에이전트에게 맡기기

고치는 일을 직접 하지 않는다. 구간마다 하위 에이전트를 새로 띄운다. 원고를 쓴 대화의 맥락이 섞이면 효과가 없기 때문이다. 구간이 여럿이면 한 번에 여러 개를 띄운다.

하위 에이전트에게 줄 지시문은 스크립트가 만든다.

```bash
python TOOLS brief 원고.md 시작줄 끝줄 > /tmp/brief_시작줄.txt
```

이 출력을 그대로 하위 에이전트의 지시문으로 쓴다. 지시문에는 판정 기록 전체, 지킬 조건, 해당 구간의 줄이 들어 있다. 지시문에 자신의 해석이나 "이런 문장을 조심하라" 같은 말을 덧붙이지 않는다. 덧붙인 말이 판정 기록보다 강하게 작용한다.

하위 에이전트는 고친 줄만 `줄 번호<탭>고친 내용` 형식으로 답한다. 답을 구간별 파일로 저장한다.

### 3. 수정 반영하기

```bash
python TOOLS apply 원고.md 답1.tsv 답2.tsv ... --out 원고.polished.md
```

스크립트는 표의 세로선 개수가 달라진 줄, 구간 밖의 줄, 내용이 같은 줄을 버리고 나머지를 반영한다. 바뀐 줄 목록은 `원고.polished.changes.json`에 남는다. 원본 파일은 건드리지 않는다. 사용자가 원본을 덮어쓰라고 하면 그때 덮어쓴다.

### 4. 사용자에게 확인받기

```bash
python TOOLS sample 원고.polished.md --n 20
```

바뀐 줄 가운데 20개가 원문과 수정문으로 나온다. 번호를 붙여 사용자에게 보여 주고 "아직 어색한 번호"를 묻는다. 바뀐 부분만 짧게 보여 준다. 이 단계를 건너뛰지 않는다. 판정 기록은 이 확인으로만 늘어난다.

### 5. 판정 기록에 추가하기

```bash
python TOOLS record 원고.polished.md --n 20 --bad 3,7
```

사용자가 괜찮다고 한 수정은 "어색한 원문과 받아들인 수정" 쌍으로, 아직 어색하다고 한 수정문은 '어색' 판정으로 기록된다. 사용자가 직접 고쳐 준 문장이 있으면 `--fix '3=고친 문장'`으로 함께 넘긴다.

새 판정은 작업 중인 프로젝트의 `.korean-polish/labels.jsonl`에 쌓인다. 이 파일을 커밋해야 다음 세션에 남는다. 스킬에 들어 있는 `labels.jsonl`은 처음 기준이고, 두 파일을 합쳐서 쓴다.

통과율이 낮으면(대략 80% 미만) 추가된 판정으로 2번부터 한 번 더 돌린다.

## 하지 않는 것

- 원고의 내용, 구성, 사실 관계를 바꾸지 않는다. 문장만 고친다.
- 판정 기록에 없는 기준을 만들어 적용하지 않는다.
- 사용자가 확인하지 않은 수정을 판정 기록에 넣지 않는다.
- 코드, 링크, 그림 지시(`svg:`, `flow:` 등)는 고치지 않는다.

## 알려진 한계

- 판정 기록은 드론 기술 카드뉴스 기획서의 문장에서 시작했다. 다른 종류의 글에서는 처음 몇 번의 확인으로 판정을 보태야 기준이 맞는다.
- 제목이나 메모처럼 짧게 써야 하는 줄을 서술문으로 늘이는 경향이 있다. 사용자가 그런 수정을 어색하다고 표시하면 다음 실행부터 줄어든다.
- 이 절차는 API를 직접 호출하는 방식으로 검증했다(수정 35개 가운데 32개를 편집자가 받아들임). 하위 에이전트 방식의 통과율은 따로 재지 않았다.
